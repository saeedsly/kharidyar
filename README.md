# خریدیـار (KharidYar) 🛒

**مدیریت خرید و چک‌لیست؛ OCR ابری فارسی‌محور با fallback آفلاین روی دستگاه**

- **سازنده و صاحب اثر:** سعید سالاری (Saeed Salari)
- **وب‌سایت پروژه:** [saeedsly.github.io/kharidyar](https://saeedsly.github.io/kharidyar/)
- **سیاست حریم خصوصی:** [Privacy Policy](https://saeedsly.github.io/kharidyar/privacy.html)
- **آخرین APK عمومیِ شناخته‌شده:** [KharidYar-Android7-v1.4.2.apk](https://github.com/saeedsly/kharidyar/releases/download/v1.4.2/KharidYar-Android7-v1.4.2.apk)

## ویژگی‌ها

- ثبت و ویرایش چک‌لیست، فاکتورها و بودجه در حافظهٔ خصوصی برنامه.
- OCR ابریِ Microsoft Azure Document Intelligence Read برای متن فارسی/چندزبانه، با parser داخلی برای استخراج مبلغ‌ها؛ اگر cloud خاموش یا در دسترس نباشد، OCR آفلاینِ داخل APK اجرا می‌شود.
- OCR ابری به‌صورت پیش‌فرض فعال است و می‌توان آن را از پنجرهٔ اسکن خاموش کرد. در حالت روشن، تصویر از طریق Supabase Edge Function به Azure فرستاده می‌شود؛ تصویر در سابقهٔ فاکتورها ذخیره نمی‌شود.
- گزارش ماهانه بر پایهٔ تقویم شمسی و تجمیع چند فاکتورِ یک روز.
- خروجی و بازیابی پشتیبان JSON از داخل برنامه.
- حالت OCR آفلاین به اینترنت نیاز ندارد. OCR ابری برای ارسال تصویر به Azure به اینترنت و مجوز عادی INTERNET در Android نیاز دارد؛ با خاموش‌کردن گزینهٔ ابری، تصویر از دستگاه خارج نمی‌شود.

## راه‌اندازی OCR ابری رایگان

برنامه از مدل `prebuilt-read` در Azure Document Intelligence استفاده می‌کند؛ این مدل برای متن فشردهٔ سند طراحی شده و Persian را پشتیبانی می‌کند. در پلن رایگان F0، سهمیهٔ رسمی ۵۰۰ صفحه در ماه است؛ حداکثر اندازهٔ هر درخواست ۴ مگابایت است و پلن رایگان حداکثر دو صفحه از هر درخواست را تحلیل می‌کند. چون رسیدهای خیلی بلند به چند برش تقسیم می‌شوند، هر برش ممکن است یک صفحه از سهمیه حساب شود.

ساخت resource به حساب و Azure subscription نیاز دارد؛ بسته به منطقه و وضعیت حساب، ممکن است Azure برای ثبت‌نام روش پرداخت بخواهد. برای فعال‌کردن سرویس، یک resource از نوع **Document Intelligence** در پلن **F0 (Free)** در Azure بسازید و endpoint و key آن را فقط در بخش **Supabase Dashboard → Edge Function Secrets** با نام‌های `AZURE_DI_ENDPOINT` و `AZURE_DI_KEY` وارد کنید. کلید Azure را در APK، GitHub یا چت قرار ندهید. Supabase Edge Function با نام `azure-read` این کلیدها را server-side نگه می‌دارد. تا پیش از تنظیم این دو secret، برنامه تصویر را به سرویس نمی‌فرستد و خودکار از OCR محلی استفاده می‌کند.

برای جلوگیری از هزینه، resource را در پلن F0 نگه دارید و سقف رایگان Azure را بررسی کنید؛ پلن‌ها و سهمیه‌ها ممکن است با گذشت زمان تغییر کنند.

## ساخت نسخهٔ Android

ساخت APK از گردش‌کار GitHub Actions انجام می‌شود. خروجی آن به شکل artifact همان اجرای workflow در دسترس است؛ این روند APK را به‌صورت خودکار در مخزن عمومی یا سرویس ابری منتشر نمی‌کند.

تا زمانی که کلید امضای پایدار در GitHub Actions تنظیم نشده باشد، workflow از کلید موقت استفاده می‌کند و خروجی را `test-only-key` می‌نامد. چنین APKای برای نصب تازه و آزمایش است و نمی‌تواند روی نسخه‌ای با امضای دیگر به‌روزرسانی شود. برای انتشارهای قابل‌به‌روزرسانی باید کلید خصوصی پایدار و امن در GitHub Actions تنظیم شود؛ فایل کلید نباید در مخزن قرار گیرد.
